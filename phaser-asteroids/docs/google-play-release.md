## Create and protect an upload key (human step; not performed)

Enable Google Play App Signing. Prefer Google-managed app signing keys; retain a separate upload key locally. Confirm existing signing history before creating anything. If no upload key exists, a human can run JDK 21 `keytool` interactively, choosing a path outside the repo:

```powershell
keytool -genkeypair -v -keystore 'C:\PrivateKeys\spacearcade-upload.jks' -alias spacearcade-upload -keyalg RSA -keysize 4096 -validity 10000
```

This command is an instruction, not an artifact generated by this task. Let keytool prompt for passwords. Keep the keystore and recovery information in encrypted, access-controlled backups. Never put a keystore, passwords, signing exports or an admin/API secret in Git, `VITE_*`, shell history, CI logs, chat or Gradle command arguments. Ignore rules cover common key containers, but keeping them outside the checkout is the primary protection. Share only the public certificate with Play when needed. Upload-key reset and app-signing-key rotation are different operations.

Set `ASTEROIDS_UPLOAD_STORE_FILE`, `ASTEROIDS_UPLOAD_KEY_ALIAS`, `ASTEROIDS_UPLOAD_STORE_PASSWORD`, `ASTEROIDS_UPLOAD_KEY_PASSWORD` in a private local process environment or CI secret store. Read passwords with a masked prompt or secret manager. Example for a local PowerShell session:

```powershell
$env:ASTEROIDS_UPLOAD_STORE_FILE = 'C:\PrivateKeys\spacearcade-upload.jks'
$env:ASTEROIDS_UPLOAD_KEY_ALIAS = 'spacearcade-upload'
function Set-UploadPassword([string]$Name) {
    $secretValue = Read-Host $Name -AsSecureString
    $secretPointer = [Runtime.InteropServices.Marshal]::SecureStringToBSTR($secretValue)
    try {
        [Environment]::SetEnvironmentVariable($Name, [Runtime.InteropServices.Marshal]::PtrToStringBSTR($secretPointer), 'Process')
    } finally {
        [Runtime.InteropServices.Marshal]::ZeroFreeBSTR($secretPointer)
        $secretValue.Dispose()
    }
}
Set-UploadPassword 'ASTEROIDS_UPLOAD_STORE_PASSWORD'
Set-UploadPassword 'ASTEROIDS_UPLOAD_KEY_PASSWORD'
```

Environment variables necessarily become readable to the build process. Use a trusted machine, avoid `--debug`/environment dumps, and unset all four immediately after building (also in failure cleanup). Do not enable a Gradle build scan when secrets are present. A partial signing configuration fails immediately; missing credentials fail release tasks unless explicitly producing audit-only unsigned output. No debug-key fallback exists.

## Reproduce and verify a build

From `phaser-asteroids`, with reviewed source and lockfiles:

```powershell
$env:JAVA_HOME = 'C:\Path\To\jdk-21'
npm ci
npm ci --prefix server
npm test -- --maxWorkers=4
npm run typecheck --prefix server
npm run test:android-build
npm run android:sync
Push-Location android
try {
    .\gradlew.bat :app:bundleRelease :app:assembleRelease :app:lintRelease --no-daemon --console=plain
    if ($LASTEXITCODE) { throw 'Android release build failed' }
} finally { Pop-Location }
.\scripts\inspect-android-release.ps1
```

Check every command's exit code before continuing (PowerShell does not automatically stop on native nonzero exits). `.env.android` contains only the public production HTTPS API origin. `build:android` checks that origin, frozen rules, release registry and bundled scripts; Capacitor packages `dist-android`, excluding the server SSR bundle. Re-run sync after any frontend change. An Android Gradle task alone does not rebuild web assets. These commands reproduce the release process; they do not claim byte-identical signed ZIPs across machines/timestamps.

For verification **without signing credentials**, run the inspector with `-Unsigned` and use the same Gradle command with `-PallowUnsignedRelease=true`. That produces `android/app/build/outputs/bundle/release/app-release.aab` and `outputs/apk/release/app-release-unsigned.apk`, which must not be uploaded as a signed release. Build type remains release (WebView debugging disabled). The actual signed AAB has the same path; copy approved artifacts to a protected release archive and record SHA-256, source revision/dirty diff, lockfile hashes, tool versions, native versions and rules/schema. Inspect the artifact you will upload, not an earlier unsigned one. Verify signed AAB certificate with JDK `jarsigner -verify -verbose -certs <aab>`; compare fingerprint to the registered upload certificate. Use SDK `apksigner verify --print-certs <apk>` for signed APKs. Do not print passwords.

Without `-Unsigned`, the inspector (since 2026-11-12) also requires both signatures to verify, refuses the Android debug certificate, refuses a debuggable APK in either mode, and refuses any bundled draft privacy marker (`[PRIVACY CONTACT PENDING]`, `DRAFT PRIVACY POLICY - REVIEW PENDING`); it lists every problem before failing. `-Unsigned` reports the markers as warnings. `-ApkPath`/`-AabPath` inspect copies. For phone testing before signing exists, follow the [phone test checklist](phone-test-checklist.md): it re-signs a copy of the unsigned release APK with the local debug key for sideloading only.

## Manifest, SDK and memory-page checks

Source targets/compiles API 36, min API 24; this satisfies the [current new-app API requirement](https://support.google.com/googleplay/android-developer/answer/11926878?hl=en) checked on 2026-11-03. Release is landscape; backup and cleartext disabled; launcher exported, FileProvider private. Inspect merged release manifest and lint report under `android/app/build/`, then run the artifact inspector. Expected permissions are INTERNET, VIBRATE and the generated signature-only AndroidX dynamic-receiver permission, with no advertising ID, location, microphone/camera or storage access. Confirm `debuggable` is false in release output. Test minimum-supported and current Android behavior, landscape, safe areas and Back on real hardware.

The inspector checks APK and AAB for **all** `.so` files, not merely direct project code. No native shared objects means no bundled ELF/ZIP native-library alignment defect; Android's WebView provider is supplied by the OS. If any dependency adds `.so` files, the inspector intentionally stops: use Android's [16 KB instructions](https://developer.android.com/guide/practices/page-sizes) for ELF LOAD alignment, bundletool `dump config` / PAGE_ALIGNMENT_16K and `zipalign -c -P 16 -v 4` on generated APKs. The current provider page discusses a February 1, 2027 update-enforcement date; do not treat that as permission to ship an incompatible first release. Test on a 16 KB emulator/device (`adb shell getconf PAGE_SIZE` must print `16384`), then verify the Play-generated split APKs and App Bundle Explorer page-size result. A Samsung smoke test on a 4 KB device does not cover this.
