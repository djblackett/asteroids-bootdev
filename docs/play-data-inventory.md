# Android privacy inventory and proposed Data safety answers

Audit date: 2026-11-03; moderation follow-up 2026-11-04. Branch: `dev`. Scope: Capacitor Android application, browser code shared with it, Cloudflare Worker and D1 schema. Root Python game's scores/logging are not packaged in the Android game. No cloud account settings or production data were read or modified. Reporting, erasure and the extended moderation workflow below were implemented locally at audit time and **have been live in production since 2026-11-04** (Worker `c2aef78f`, D1 migrations 0001-0004; see the [Stage 2 record](release-preflight.md#stage-2-production-worker-deployment-2026-11-04)). The proposed answers below are still unconfirmed against provider settings. See [moderation audit and operator guide](leaderboard-moderation.md).

## Permissions and dependencies

Direct runtime dependencies: Phaser 4.2.1, Capacitor Android/Core 8.6.0, Capacitor App 8.1.2 (resolved versions in lockfile). App plugin provides lifecycle, Back and exit/minimize integration. Built-in Capacitor plugins support WebView/system bars; CapacitorHttp is not enabled. Android transitive libraries are AndroidX and Cordova bridge dependencies. Vite/TypeScript/Vitest/Playwright and Wrangler are development/build tooling, not advertising or analytics clients in the app. The Google Services Gradle classpath/template conditional is not evidence of Firebase data collection; no `google-services.json` or Firebase runtime dependency was found. Recheck the resolved release dependency graph and final manifest for each upload.

Source manifest permissions are INTERNET and VIBRATE (normal, no runtime consent dialog). No location, contacts, camera, microphone, storage, advertising ID, notification or billing permission. Launcher Activity exported; FileProvider not exported, with temporary URI grants; no app file-sharing flow found. Cleartext traffic and Android backup are now disabled explicitly, with all storage domains excluded from Android 12+ cloud backup and device transfer in `data_extraction_rules.xml`. The final merged release manifest confirms only INTERNET, VIBRATE and the internal signature-level AndroidX dynamic-receiver permission. The resolved runtime graph contains no Firebase, Google Play Services, advertising or analytics dependency. AndroidX startup initializes lifecycle/profile/emoji helpers; any OS font-provider/WebView/Play diagnostics remain platform behavior requiring provider verification, not custom telemetry we can certify from this checkout. OEM transfer behavior still needs a device check. See [Android backup guidance](https://developer.android.com/identity/data/autobackup).

## Proposed Play declaration (review before submission)

Answer **Yes** to collection. Proposed types and purposes below cover this version after its backend migration/deployment. Collection includes optional online features even without accounts.

| Play type | Proposed answer | Qualification |
| --- | --- | --- |
| Personal info / Name | Collected; optional; app functionality; not ephemeral | Nickname. Do not classify it solely as User IDs: Google's Name definition explicitly includes nicknames |
| App activity / Other actions | Collected; optional for gameplay submission/reporting; app functionality and fraud prevention/security/compliance; not ephemeral | Gameplay, verification results, controls and report actions |
| Device or other IDs | Conservatively collected; fraud prevention/security/compliance; not ephemeral | Salted IP-derived identifier. Confirm classification against current Console guidance; it is a network-derived pseudonym, not Android ID or advertising ID |
| Personal info / User IDs | No account ID collected; review whether IP-derived linkage requires an additional declaration | Random score/run IDs identify events, not authenticated people. Do not invent accounts |
| App activity / App interactions | Review, alongside Other actions | No tap/page analytics. Normal endpoint/request logs might expose interactions; confirm provider logging before deciding |
| Diagnostics | Provider verification required | No crash/diagnostic SDK in app; operational Worker errors/request logs may qualify depending on actual captured fields/use. Do not select Analytics just because operational metadata exists |
| Approximate location | No application geolocation; provider verification required | Worker does not infer location. If configured Cloudflare processing/logging uses IP-derived location on our behalf, disclose that use |
| Email address | No in-app field. Public contact `privacy@davidandrea.ca` (confirmed 2026-11-12); reassess once the mailbox workflow is documented | Voluntary external email contact is distinct from Android API collection; describe correspondence handling honestly |
| Other UGC | Review only for residual content not already classified as Name | Nicknames already belong in Name; report reason is fixed selection, no free text |

No app collection found of photos, user audio, contacts, files/documents, health, finances, messages, installed apps, searches, browsing history or precise location. Audio assets are bundled music, not recordings of players.

**Sharing:** actual public disclosure exists. Proposed form answer may exclude Cloudflare processing solely on our behalf under the service-provider exception and nickname/score publication under the expected user-initiated public-sharing exception, now disclosed beside Submit. This is conditional on provider terms/practices and the approved UX. Do not equate “no sharing required in the form” with “no data leaves the app.” If an exception does not apply, declare the affected types shared.

**Required versus optional:** nickname, replay and reports are optional (Practice/Skip remain usable). IP/request metadata may be required for automatically refreshed online menus; do not mark all identifiers optional until the actual provider capture and offline behavior have been reviewed. The application writes issuer hashes only when a player requests ranked play, and report hashes only on reporting.

**Transport encryption:** proposed Yes for the release: production URL is HTTPS, release manifest forbids cleartext, origin overrides are disabled in native app. Development HTTP tests are not the distributed build. **Deletion requests:** Yes only after the contact is live, staff process is ready and erasure route deployed. **Account deletion:** not applicable; there are no accounts. No independent security review/certification or Families compliance badge is claimed. Decide target ages/content rating before Play setup.

Google currently exempts apps exclusively on the internal testing track from completing Data safety, but this inventory prepares later tracks; internal testing does not make inaccurate policy text acceptable. See [Data safety guidance](https://support.google.com/googleplay/android-developer/answer/10787469?hl=en) and [User Data policy](https://support.google.com/googleplay/android-developer/answer/10144311?hl=en).

## Provider verification still required

Verify Cloudflare plan/DPA role, data regions/subprocessors, Workers observability and sampling, invocation fields (headers/IP/geolocation), live tails, security logs, Logpush destinations, access controls and retention. The checked-in Wrangler config has no observability section; dashboard/deployment state cannot be inferred from that omission. Verify no request-body capture or external exports. [Workers Logs](https://developers.cloudflare.com/workers/observability/logs/workers-logs/) currently documents 3-day Free/7-day Paid retention; these are provider defaults, not proof of enabled production logging. [D1 Time Travel](https://developers.cloudflare.com/d1/reference/time-travel/) documents recovery history up to 30 days on Paid/7 on Free, separate from SQL deletion; verify this database's plan/storage and any exports. Review the [Cloudflare DPA](https://www.cloudflare.com/cloudflare-customer-dpa/). Preserve erasure decisions outside a restored snapshot so deleted entries are not republished after recovery. Do not claim exact provider deletion deadlines until verified.
